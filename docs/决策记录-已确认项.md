## 第 1 条详解：能不能「只做一种，React/Vue 都能用」？

### 结论

**可以「只维护一套核心逻辑」；不能「只做一个 React 组件却让 Vue 直接当组件用」。**

原因：React 的 JSX 组件和 Vue 的 SFC/组件实例是两套运行时，npm 里没有一种「万能 UI 组件」能被两边零适配直接 `<AiChart />`。

### 推荐形态（满足你的诉求）

**一个 npm 包 `ai-echarts`，三个入口：**

```text
ai-echarts          → 纯 core（ChartSpec / compile / recommend）任意框架可 import
ai-echarts/react    → React 薄组件
ai-echarts/vue      → Vue 薄组件
```

使用方式：

```ts
// 任意端：只拿逻辑
import { compile, type ChartSpec } from 'ai-echarts';

// React 项目
import { AiChart } from 'ai-echarts/react';

// Vue 项目
import { AiChart } from 'ai-echarts/vue';
```

- **你侧工作量**：一套 Spec/编译（主体）+ 两层很薄的 adapter（生命周期/ref）。  
- **消费方感受**：装一个包，按框架选子路径即可。  
- 这比「两个独立包 `@xxx/react` + `@xxx/vue`」更接近你说的「只做一种」。

若极端只发 core、不做 adapter：两边都能 `import { compile }`，但各自还要手写 `echarts.init`，第三方体验差，**不推荐作为对外主形态**。

## 第 4 条白话：什么叫「一期是否必须上 NL 出图」？

指的是产品第一种用法还是第二种：

| 模式 | 用户怎么用 | 要不要 DeepSeek Key |
|------|------------|---------------------|
| **A. 声明式组件（建议一期）** | 用户自己（或业务代码）传入 `data` + `ChartSpec`（或字段映射），组件直接画图 | **不要** |
| **B. 自然语言出图（AI）** | 用户说「按地区对比销售额」，系统调大模型生成 Spec 再画图 | **要**（你已定 DeepSeek） |

「一期是否必须上 NL」= **第一个版本要不要做 B**。

- **不是必须**：先把 A 做好（通用组件 + Demo），AI 接口先预留，接上 Key 再开 B。  
- **必须做 B**：实现期就要配置 `DEEPSEEK_API_KEY`，否则 NL 链路无法联调。

**已确认：一期要真 AI（模式 B 必做）。**

一期同时交付：

1. **A**：`ai-echarts` + `/react` + `/vue`（Spec 驱动渲染）  
2. **B**：NL → ChartSpec（DeepSeek `v4-flash` / `v4-pro`），Demo 可对话框出图  

无 Key 时本地可降级提示「未配置 API Key」；**联调与验收需要你提供 DeepSeek Key**（勿提交进仓库，用环境变量）。

## 第 5 条：DeepSeek 预留

| 项 | 值 |
|----|----|
| Provider | `deepseek`（OpenAI 兼容 `https://api.deepseek.com`） |
| 默认模型 | `deepseek-v4-flash`（快、便宜，适合单图 Spec） |
| 可选升级 | `deepseek-v4-pro`（看板规划 / 难消歧） |
| 环境变量（预留） | `AI_ECHARTS_LLM_PROVIDER=deepseek` · `AI_ECHARTS_LLM_API_KEY=` · `AI_ECHARTS_LLM_MODEL=deepseek-v4-flash` |

实现前你只需在要用真 AI 时提供 Key；组件库发包本身不带 Key。

## 第 6 条：无业务样例时的数据约定

不做「固定业务表结构」，只约定**通用输入形态**：

```ts
// 一行一条记录；列名任意；类型运行时推断
type DataRow = Record<string, string | number | boolean | null | undefined>;
type ChartInput = {
  data: DataRow[];
  spec: ChartSpec; // 或由 AI/规则从 data + 意图生成
};
```

Demo / 测试使用**合成数据**（销售/访问量等假数据），仅用于展示能力，不代表业务 schema。  
业务方接入时：自带任意列的 `data` + 自己的 `spec`（或日后 NL）。
